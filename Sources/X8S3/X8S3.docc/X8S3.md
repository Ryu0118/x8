# ``X8S3``

An optional S3-compatible storage adapter for X8 compilation-cache records.

## Overview

``S3Storage`` implements the provider-neutral `X8Storage.CASStore` and
`X8Storage.ActionCacheStore` contracts using Soto. It owns object-store requests,
S3-compatible endpoint configuration, and the versioned envelopes used for
CAS objects and Action Cache values.

`S3Storage` accepts an injected `FileManagerProtocol` for local CAS staging.
The default uses the live Foundation `FileManager`; remote object semantics
remain independent of that implementation detail.

## Ownership and data flow

`S3Storage` owns the actor-isolated mapping from X8 storage protocols to
object keys in one configured bucket. Internally it separates three
concerns: translation to and from Soto request and response types, the fixed
category prefixes (`cas/`, `action-cache/`, and so on), and the versioned X8
envelope. None of them is a cache policy.

CAS input is staged locally so the backend can compute its opaque identifier
before uploading and replay the body when needed. Reads decode the bounded
envelope header and keep the payload lazy. `shutdown()` releases the live
clients; injected clients are not owned or shut down by the storage actor.

| Record | Object key | Contents |
| --- | --- | --- |
| CAS object or blob | `cas/<hex CASDataID>` | Versioned envelope: reference list, then payload |
| Action Cache value | `action-cache/<hex key>` | Encoded `entries` map |
| In-progress upload | `staging/<hex identifier>` | Staged body before the final key is known |
| Retention anchor | `retention/<hex identifier>` | GC roots for purge planning |
| Public-read probe | `cas/_x8-probe`, `action-cache/_x8-probe` | Fixed marker; non-hex, so listing and purge skip it |

The hex encoding is a key-safe spelling of the opaque bytes Xcode supplied;
it is not a new identifier.

## Signed and public access

``S3StorageConfiguration`` holds optional signed API access and an optional
public read URL, at least one of which is set. Writes, listing, deletion, and
retention always use the signed API. Xcode-path reads use the public URL when
one is configured, and the signed API otherwise. Soto and its credential
provider are constructed only when signed API access is configured, so a
public-read-only profile never resolves credentials.

Public reads use a separate AsyncHTTPClient that sends no headers and does
not follow redirects. A `404` is a miss. A `403` is a miss only when its body
is an S3 `AccessDenied` error and ``S3PublicReadVerifier`` has fetched the
namespace's probe object. S3 and MinIO return the same `AccessDenied` for a
missing key as for a real denial when anonymous `s3:ListBucket` is not
granted, so the probe is what proves read access. The verdict is re-checked at
most once a minute. Every other `403` and unexpected status is thrown, so a
permission problem never looks like an empty cache. When
`publishesReadProbes` is set, ``S3ReadProbePublisher`` creates each probe after
the first write to its namespace in each process.

The module is enabled by the `S3` package trait. `X8Kit` remains independent
of this module, so custom frontends can provide another storage implementation
without importing Soto.
